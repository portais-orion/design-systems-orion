## O que é

O Design System Orion é a base oficial para criação, padronização e evolução dos portais das empresas do grupo. Não é uma biblioteca da Supertrans nem uma cópia do Aurora — é a curadoria do melhor dos dois, mantida como plataforma.

## Pacotes

| Pacote | Camada | Conteúdo |
|---|---|---|
| `@portais-orion/tokens` | 0 | tokens semânticos + temas por marca (CSS puro) |
| `@portais-orion/ui` | 1 | 26 primitives (Base UI + Tailwind v4 + cva) |
| `@portais-orion/blocks` | 2 | composições genéricas: DataTable, PageHeader, Pagination, ConfirmDialog... |

## Instalação (produtos)

```sh
pnpm add @portais-orion/tokens @portais-orion/ui @portais-orion/blocks
```

```css
/* entrada CSS do produto */
@import "tailwindcss";
@import "tw-animate-css";
@import "@portais-orion/tokens/base.css";
@import "@portais-orion/tokens/themes/supertrans.css"; /* UM tema por produto */
@source "../node_modules/@portais-orion/ui/src";
@source "../node_modules/@portais-orion/blocks/src";
```

## Temas

Marcas são CSS, nunca props: os componentes usam apenas tokens semânticos (`bg-primary`, `text-muted-foreground`) e cada marca redefine as CSS variables via `[data-brand]`. Marcas disponíveis: **Supertrans** e **Aurora** — alterne pela toolbar "Marca" acima. Detalhes em *Fundações → Tokens*.

## Regras principais

- Não usar cores hardcoded em componentes (hex só em `packages/tokens/src/themes/`).
- Não colocar domínio de negócio nos packages compartilhados.
- Não usar Radix (Base UI é o primitivo headless oficial).
- Não importar arquivos dos portais.
- Todo componente compartilhado deve ter story, validada nas duas marcas.

## Qualidade

Este Storybook é o quality gate do núcleo: **accessibility checks** (painel Accessibility em cada story), **visual tests** (addon Chromatic; nuvem requer `CHROMATIC_PROJECT_TOKEN`), **component tests** (addon Vitest — stories rodam como testes em Chromium headless) e esta **documentação MDX**. Fluxo completo: `docs/architecture/quality-gates.md` no repositório.
